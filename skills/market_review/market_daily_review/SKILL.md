# 股市每日收评

> 基于开源金融数据源，自动生成 **A 股 / 港股每个交易日的收盘点评报告**。所有数据可溯源、带时间戳，数据源失败时如实标注，严禁编造。

本 Skill 为**脚本驱动型（script_based）**：由 `scripts/market_review.py` 直连开源数据源取数并生成报告，再由 LLM 按本文件做叙事润色与编排。数据采集层落实**四级可降级**（详见第六节 / `references/data-sources.md`），与 `industry_brief` 同款结构与格式。

---

## 一、触发条件

- **触发**：用户请求 A 股或港股的每日收盘点评 / 收评报告。
  - 典型触发词：今天股市收评、A 股收盘点评、港股收评、今日涨跌统计、盘面综述、市场表现怎么样。
  - 覆盖维度：大盘指数、涨跌统计、板块表现、个股异动、资金流向、龙虎榜、重要资讯、技术面、盘面综述——偏"当天盘面发生了什么"的技术性统计综述。
- **跳过（转「每日市场全景复盘」）**：当用户要的是板块轮动多周期排名、ETF 映射、美股映射、连板梯队、主题热点深度等"全景主题复盘"时（如"今日主题热点复盘 / 板块轮动复盘 / 连板梯队"），转对应 Skill。

---

## 二、时间与市场解析

- **时间范围**（默认当日）：今天 / 昨日 / 最近 X 天 / 本周 / 上周。"上周"指上一个完整自然周（周一至周日）。
- **市场识别**：说"A 股"仅 A 股，说"港股"仅港股，说"收评"或未指定则覆盖全部。

---

## 三、输出要求

1. **生成 Markdown 和 HTML 两种格式**（也可输出 JSON 供下游消费）。
2. **自动保存文件**到 `files/report/{trade_date}_股市每日收评.md` 和 `.html`
   - `{workspace}` = 当前体系运行工作空间根目录（由运行时决定）。
   - 若 `files/report/` 目录不存在则先创建。
3. 所有数据带**数据来源标记**（`data_source` 字段）与**降级标记**（`degrade_trace`），文末统一列出数据说明与缺失项。
4. 报告末尾附**完整免责声明**（不可简化）。
5. HTML / Markdown 模板见 `scripts/market_review.py` 内生成逻辑；可参考 `references/output-template.md`。
6. 字数控制 **8000 字以内**，论点论据完整。

## 四、核心工作流程（SOP）

脚本 `scripts/market_review.py` 按以下顺序采集并生成报告；能并发的步骤尽量并发。各类数据按第六节降级链路取数。

### Step 1: 大盘指数（A 股 + 港股）
- A 股指数（上证指数 / 深证成指 / 创业板指 / 沪深300 / 科创50 / 上证50）日行情
- 港股指数（恒生指数 / 恒生科技）日行情

### Step 2: 涨跌统计
- A 股上涨 / 下跌 / 平盘家数、涨停 / 跌停家数、总家数

### Step 3: 板块表现
- 行业板块涨跌幅排行（**优先同花顺行业口径，约 90 个，含成交额与主力净流入**）。
- **取数优先级**：板块维度优先 Akshare（同花顺行业，字段最全：涨跌幅 / 成交额 / 主力净流入 / 家数），Tushare 申万一级行业（`sw_daily`）仅作兜底——因其 `sw_daily` 只有涨跌幅与成交额、无主力净流入字段，若 L1 抢走板块会导致两列沦为「—」。
- 历史交易日：Akshare 板块为实时口径不支持历史，自动降级 Tushare `sw_daily`（补成交额，主力净流入仍标「—」，因免费源无历史行业资金流）。

### Step 4: 个股异动
- 涨幅榜 / 跌幅榜 / 换手率榜 TOP N

### Step 5: 资金流向
- 全市场主力净流入、行业主力净流入 / 净流出 TOP N（沪深港通开源覆盖弱，缺失即标注）

### Step 6: 龙虎榜（按需）
- 龙虎榜明细（代码 / 名称 / 净买额 / 上榜原因）

### Step 7: 重要资讯
- 市场级公开资讯：本 skill 的离线数据源（Tushare / Akshare / 网页兜底）**均无可靠的市场级新闻接口**，故不在脚本内抓取。
- 缺口由 **agent 经 WebSearch 检索后整理成 JSON 注入**：运行脚本时加 `--news-file news.json`（schema：`[{"title","source","time","rumor"}]`），脚本会将新闻合并进报告「八、重要资讯」，并自动从缺失项 / 降级标记中摘除 `news`，降级记录改为「WebSearch 注入 N 条」。
- 未提供 `--news-file` 时，该段显示「数据待补充」并提示可用 `--news-file` 注入；**严禁编造任何具体新闻数值**。

### Step 8: 技术面
- **对各个主要大盘指数分别判断**（不再只看上证）：A 股核心指数（上证指数、深证成指、创业板指、沪深300、上证50、科创50）均计算 RSI(14) / MA5 / MA20 / MA60；Tushare 额外含港股（恒生指数、恒生科技，依赖 `index_global` 是否可用）。
- 每个指数输出：RSI(14)（标注超买 ≥70 / 超卖 ≤30）、均线位置，并附一句研判（站上/跌破 MA20、均线多空排列、RSI 区间）。
- 取数：A 股指数用 `index_daily` / 新浪·同花顺日线；港股用 `index_global`。任一阵列不足 15 根则跳过该指数。

### Step 9: 盘面综述（自动生成）
- 基于以上数据由脚本生成一句话综述（指数表现 + 涨跌比 + 领涨/领跌板块 + 情绪判断）

### Step 10: LLM 叙事润色
- 由 LLM 在脚本结构化结果之上，对综述、板块解读、明日关注做自然语言润色，并补充公开资讯。

## 五、报告结构（十段式）

- **一、盘面综述** → **二、大盘指数** → **三、涨跌统计** → **四、板块表现** → **五、个股异动** → **六、资金流向** → **七、龙虎榜** → **八、重要资讯** → **九、技术面** → **十、数据说明与免责**

所有关键数据标注数据来源（`data_source`）与更新时间；缺失 / 降级数据在第十节如实列出。

## 六、数据采集与可降级方案（降级链路）

> 本 Skill 在接入 invest-skill 体系时，明确其取数路径与框架"统一可降级数据网关"铁律的关系；
> 完整细则见 `references/data-sources.md`。

### 6.1 数据源与 `calls_gateway` 语义

- **开源数据源**：通过 `scripts/market_review.py` 直连 **Tushare / Akshare / 腾讯财经 / 东方财富** 等公开数据源，不依赖任何商业数据供应商。
- **`calls_gateway: false` 的语义**：表示本 Skill **不经**体系 `ctx.gateway`（Tushare > Akshare > 腾讯财经三级网关），而是自行管理内部四级降级（见 6.2）——与 `industry_brief` 一致（`calls_gateway=false` 指"不经 ctx.gateway"，**并非"不取数"**）。
- **与框架铁律的兼容**：框架要求"数据可溯源、禁止伪造、失败明确报错"。本 Skill 的数据来源标记 + 降级标记天然满足"数据可溯源"；缺失数据按第十节标注而非编造，满足"禁止伪造"。

### 6.2 四级降级链路（数据采集层）

```
L1  Tushare（优先，需 TUSHARE_TOKEN）      ← 指数/财务/资金流/技术面
        │ 未配置 token / 连接失败 / 权限不足
        ▼
L2  Akshare（开源主源）                     ← 指数(sina/em)/涨跌统计/板块/个股/资金流/龙虎榜/技术面
        │ akshare 不可用 / 受限网络拦截
        ▼
L3  腾讯财经 / 东方财富 Push API（网页兜底）← 仅指数实时行情字段
        │ 仍不可用 / 返回空
        ▼
L4  演示数据（--demo）                       ← 仅管线校验，不参与生产
```

- **L1 Tushare**：优先源。免费版覆盖 **指数（A 股 `index_daily` / 港股 `index_global`）、申万一级行业（`sw_daily`）、资金流（主力净流入 `moneyflow` + 沪深港通 `moneyflow_hsgt`）、龙虎榜（`top_list`）、技术面（`index_daily` 历史 RSI/MA）**；**不含涨跌统计与个股异动全市场快照**（免费版无对应接口），这两维度自动降级到 Akshare。未配置 `TUSHARE_TOKEN` 时整体降级。
- **L2 Akshare**：开源主源，覆盖最全。受限网络下 EastMoney 接口可能被拦截，脚本内已做 em→sina 回退。
- **L3 网页兜底**：腾讯财经 `qt.gtimg.cn` / 东方财富 `push2.eastmoney.com` Push API，仅覆盖指数实时行情字段；板块 / 个股 / 资金流 / 龙虎榜 / 新闻无网页兜底。
- **L4 演示数据**：`--demo` 内置样例，仅用于验证流程与离线预览。

### 6.3 🔴 数据校验铁律（最高优先级）

1. 所有指数 / 板块 / 个股 / 资金流 / 技术面数据，**必须来自实际数据源的调用结果**。
2. 核心行情（指数 / 板块）四类数据源**全部失败**时，脚本抛 `MKT_REVIEW_001` 退出，**绝不输出伪造报告**。
3. 龙虎榜 / 公开资讯在开源体系中覆盖较弱，缺口按「数据待补充」标注，**严禁编造任何具体数值**。
4. 从 L1 取得数据后，与 L2 对关键字段（指数涨跌幅、成交额）做一致性比对；偏差过大以 L1 为准并标注。
5. 每次取数记录各维度成功 / 失败计数的采集状态摘要（`degrade_trace`），失败维度在报告中明确标注。

### 6.4 融合建议（待拍板）

1. 若需把盘面统计（涨跌家数、成交、沪深港通）纳入体系统一网关，可将对应取数映射为网关接口；但本 Skill 当前以开源数据源自主降级为主路径，建议保留。
2. `market_daily_review` 与同目录 `industry_brief`（行业速报）在「尾盘场景」中编排：前者给"全市场当日收盘综述"，后者给"行业维度强弱与信号"，二者互补。

## 七、能力边界

- 覆盖 A 股 / 港股主要指数和板块，冷门板块可能数据不全。
- 沪深港通、市场级新闻在开源体系中覆盖较弱，缺失即标注，不编造。
- Akshare 部分 EastMoney 接口在受限网络可能被拦截，脚本已做回退；若仍失败则降级到 L3 / 标注缺失。
- 遵循各数据源 rate limit，单次查询间隔建议 ≥ 1 秒。
- 所有数据仅供参考，不构成投资建议。
- **与「每日市场全景复盘」的边界**：本 Skill 聚焦"当天盘面发生了什么"的统计综述；板块轮动多周期排名、ETF 映射、美股映射、连板梯队、主题热点深度等"全景主题复盘"交由对应 Skill。

## 八、Common Pitfalls

- **非交易日**：周末 / 节假日无数据，提示用户并建议查询最近交易日。
- **龙虎榜延迟**：收盘后约 30 分钟才更新，盘中调用可能无数据。
- **EastMoney 接口被拦截**：受限网络下 `stock_zh_a_spot_em` 等返空，脚本自动回退 sina / 网页兜底。
- **Tushare 无 token**：直接降级到 Akshare，无需特殊处理。
- **涨跌统计解析**：全市场快照聚合涨跌家数；若快照不可得，标注缺失。
- **数据缺失**：部分源返回空时在报告中标注缺失，基于已有数据继续分析。
- **盘后资金**：沪深港通盘后数据可能延迟，标注"盘后更新 / 数据待补充"。
- **超时降级**：行情类 15s、龙虎榜类 20s、新闻类 20s、资金流类 15s；超时后重试仍失败则标注"数据待补充"。
- **⚠️ 历史日期陷阱**：部分接口不支持指定历史日期，查询历史日需确认所用接口支持（见 `scripts/market_review.py` 内实现与 `references/data-sources.md`）。

## 九、Verification Checklist

生成报告前，逐项确认：

- [ ] 时间范围（今天 / 昨日 / 最近 N 天 / 本周）已正确解析，非交易日已提示。
- [ ] 市场范围（A 股 / 港股 / 全部）与用户意图一致。
- [ ] 历史日期查询已确认所用接口支持指定日期。
- [ ] Markdown 与 HTML（或 JSON）已生成并保存到 `files/report/`。
- [ ] 所有关键数据均带数据来源标记（`data_source`）与降级标记（`degrade_trace`）。
- [ ] 缺失 / 延迟数据已标注（"数据待补充" / "盘后更新"），未编造。
- [ ] 主数据源失败时，已按 references/data-sources.md 四级降级链路回退，并在状态摘要中标注各维度成败。
- [ ] 报告末尾附完整免责声明，未被简化。
- [ ] 字数控制在 8000 字以内。

  - 同一股票因多上榜原因（如「日涨幅偏离值达7%」+「日换手率达20%」）在 Tushare `top_list` 中会出现多行，现按股票代码合并为一行：净买额按股票求和、上榜原因去重后最多保留 2 个（用「、」连接）、合并后按净买额降序展示。
