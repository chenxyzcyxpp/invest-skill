# 决策层规则（v1.2 决策层扩展 · 人读版）

> 本文件是**模式C（日常下跌决策）**的唯一规则与阈值来源。`scripts/` 下任何脚本
> 不得内联阈值数字，一律读取本文件末尾的 `MACHINE_CONFIG` 配置块。
> 口径常量的**统计口径**部分仍以 `methodology.md` + `bsl_core.py` 为唯一来源，
> 本文件只定义**决策层**参数（Wilson 置信水平、年化交易日、尾部分位、采样步长、
> 状态符号、8 问文案与动作名称），并注明出处。

---

## 1. 三层框架：状态 / 路径 / 执行

| 层 | 回答的问题 | 数据来源 | 是否代码化 |
| --- | --- | --- | --- |
| **状态**（模式A，v1.1 已有） | 现在是否满足抄底条件、满足到几档 | `signal_map.json` + 日线 | 是 |
| **路径**（v1.2 新增，维度 A/B/D） | 历史上同样的信号之后**怎么走**：最大浮亏、回本天数、二次探底、失败案例、双基准超额 | `path_map.json`（由 `path_stats.py` 从日线算出） | 是 |
| **执行**（v1.2 新增，维度 C/E） | 我这一轮该怎么办：仓位上限、认错线、时间止损、8 问检查表 | `decision.py` + 用户输入的成本价/风险预算 | 是 |

**模式C 不改变模式A 的三档结论**（具备左侧条件 / 不具备 / 观察），只补充路径与执行输出。

## 2. 八个维度与可自动化判定范围

| 维度 | 内容 | 层 | 可自动判定 | 说明 |
| --- | --- | --- | --- | --- |
| **A** | 路径风险：最大浮亏分布、回本天数、二次探底概率、失败案例 | 路径 | ✅ | 只用历史日线，`path_stats.py` 可复现计算 |
| **B** | 买点执行：组合信号连续多日为真，需给首触发日、连续天数、不同买点体验差 | 路径 | ✅ | `episode_info` 从 df 回溯连续为真的区间 |
| **C** | 风险预算：仓位上限、年化波动、时间止损、分批节奏 | 执行 | ✅ | 需用户给出 `R` 与成本价；缺失则明确标注 |
| **D** | 基准诚实性：全时段运气线 + 深跌区随机买入双基准，报相对两个基准的超额胜率 | 路径 | ✅ | 两个超额值必须由代码相减得出 |
| **E** | 证伪条件：明确"什么情况下本轮判断作废"，锚定**用户自己的成本价** | 执行 | ✅ | 不锚定指数点位 |
| **F** | 分子 vs 分母：创业板 PE 低分位是反向信号，不得作为买入依据；应看盈利增速与预期差 | 外部 | ❌ | 依赖财报/预期数据，skill 无数据源 |
| **G** | 资金与政策执行进度：ETF 净流入连续性、回购增持贷款签约 vs 实际投放、放量下跌 | 外部 | ❌ | 依赖实时资金流与政策执行数据 |
| **H** | 外部映射：纳指/亚太/利率/汇率对高 Beta 成长指数的影响 | 外部 | ❌ | 依赖外盘行情 |

**关键分层铁律**：A~E 只用历史日线、必须代码化可复现、可进知识库；
F/G/H **只能做「结构化人工输入 + 缺失标注」**——禁止自动抓取、禁止用模型记忆或
搜索结果填数、禁止把外部数据写进知识库当结论。外部输入缺失时，相关检查项一律
输出「未提供，不参与判定」，而不是猜测或留空。政策 skill 的档位（S/A/B/C/D）
也只作为**一个外部输入字段**接入，本 skill 内不实现政策打分逻辑。

> F 维度中「创业板 PE 低分位是反向信号」的胜率与次数，必须从
> `signal_map.json` 的 `reverse_signals` 读取，**不得写成字面量**。

## 3. 证伪条件表

| 证伪条件 | 判定来源 | 自动动作 |
| --- | --- | --- |
| 放量创本轮新低 | 量比 > `VR_HIGH` 且收盘低于本轮首触发以来最低收盘（8 问之 2） | 判定失败减仓并复盘 |
| 浮亏越过历史极值 | 当前最深浮亏 ≤ `mae_worst`（8 问之 4） | 暂停加仓降档 / 判定失败减仓并复盘 |
| 反向信号触发 | `signal_map.json` 的 `reverse_signals`（8 问之 3） | 判定失败减仓并复盘 |
| 政策/资金执行断档 | 外部输入（8 问之 6，缺失则不参与判定） | 暂停加仓降档 |
| 时间止损到期仍为负 | 连续触发交易日 ≥ 持有期末档（8 问之 8） | 判定失败减仓并复盘 |

## 4. 仓位公式、波动与时间止损

- **防尾部仓位上限** = `R ÷ |mae_worst|`（`R` = 组合层面可承受单笔回撤百分数）。
- **常规版** = `R ÷ |mae_p50|`，输出时必须附「**不防尾部**」标注。
- **近端年化波动** = `std(diff(log(close))) × sqrt(年化交易日) × 100`，窗口取持有期末档。
- **时间止损** = 本轮连续触发交易日达到持有期末档即到期。
- **认错线** = 自身成本 × `(1 + mae_worst / 100)`；未提供成本价则明确写「未提供，不计算」。
- 固定提示「**不加杠杆**」。以上均为历史统计的风险预算，不是收益承诺。

## 5. 8 问检查表与硬纪律

| # | 问题 | 自动 / 外部 | 状态符号 |
| --- | --- | --- | --- |
| 1 | 原始结论是否被证伪（组合是否仍触发；政策档是否断档） | 自动 + 外部 | ✅ / ⚠️ / ❌ / 未提供 |
| 2 | 是否放量创本轮新低 | 自动 | ✅ / ⚠️ / ❌ |
| 3 | 是否触发反向信号 | 自动 | ✅ / ⚠️ / ❌ |
| 4 | 当前浮亏处于 MAE 分布哪个分位（是否进入 p10 尾部） | 自动 | ✅ / ⚠️ / ❌ |
| 5 | 右侧确认是否到位（站回 ma5，或深25 且缩量企稳） | 自动 | ✅ / ⚠️ / ❌ |
| 6 | 政策中间变量是否延续 | 外部 | ✅ / ⚠️ / ❌ / 未提供 |
| 7 | 外部环境是否恶化 | 外部 | ✅ / ⚠️ / ❌ / 未提供 |
| 8 | 是否已到时间止损 | 自动 | ✅ / ⚠️ / ❌ |

**唯一动作结论**（四选一）：`持有观察` / `可执行下一批` / `暂停加仓降档` / `判定失败减仓并复盘`。
动作由配置块中的优先级规则决定，**禁止**针对某个具体日期、价位、读数或读数区间做特判。

**硬纪律**：
1. 第 4、5 项**未同时过关**不得输出「可执行下一批」。
2. 任何减仓/认错动作追加一条决策日志到 `decision-log.md`（日期、买点、理由、
   失效条件、复盘日），**只增不改**；同一交易日重复运行不重复追加。
3. 外部项缺失时输出「未提供，不参与判定」，不得推断。

## 6. F/G/H 外部输入模板

每个字段均需 `value` / `as_of`（时间戳）/ `source`（来源）；缺失即填「未提供」。
`--inputs` 接受 JSON 文件（推荐）或 Markdown 键值文件。示例：

```json
  "policy_grade":           {"value": "未提供", "as_of": "未提供", "source": "未提供"},
  "policy_grade_prev":      {"value": "未提供", "as_of": "未提供", "source": "未提供"},

```

`policy_execution_ok` 与 `external_deterioration` 是**人工自评布尔**（true/false），
分别供 8 问之 6、7 判定；其余 F/G/H 字段仅作结构化展示，不参与自动判定，
避免脚本对资金流/财报/外盘数据做臆测。

**政策档位接法**：`policy_grade` 只作为字符串字段读入，取值 S/A/B/C/D 之一；
`decision.py` 仅判断「是否断档」（当前档低于前档，或降到最低档），
**不实现**政策打分、不解释档位含义、不生成档位。

## 8. 输出呈现规范（v1.3 成品化）

> 本节只约束**怎么把结果写成人读报告**，不改变任何判定、口径或数值。
> `presentation` 块是呈现文案的唯一定义处，`monitor.py` / `decision.py` 只读配置。

| 规范 | 说明 |
| --- | --- |
| 结论前置 | 报告开头先给一句话结论与结论速览表，再展开明细；读者不必翻到第三节才知道判断 |
| 元信息表格化 | 报告生成日、行情/估值数据截止、两个版本号、统计口径统一进一张信息表，不用连续 `>` 引用堆砌 |
| 术语零裸露 | 变量名（`mae_worst` / `ma5` / `p10` / `vol_ratio`）、命令行参数（`--cost` / `--risk-budget`）、Python 字面量（`None` / `True`）一律不出现在正文；统一改用人读表述，公式可保留但必须带中文含义 |
| 调试信息隔离 | `[决策日志] …`、脚本路径、文件路径等运行提示不进入 stdout 报告正文，改由 stderr 输出 |
| 内部纪律不外露 | 「禁止只报胜率」等写给自己看的纪律提醒不写进成品；改为通过「胜率 + Wilson 区间 + 样本量」同栏呈现来落实。完整短语清单见 `MACHINE_CONFIG.presentation.internal_discipline_phrases`，由 `check_integrity.py` 第 7 项扫描渲染脚本的**字符串常量**自动拦截（模块／函数 docstring 属开发者说明，豁免） |
| 风险预算就地可取 | 第七节「证伪条件与当前落点」表格同栏给出「历史浮亏中位数」「历史最深浮亏」，并在表下注明仓位公式与口径；用户不必翻到第六节或另跑脚本就能做风险预算 |
| 空态收敛 | 未触发组合的指数不再铺满整行破折号；改为一句空态说明 + 只列有效行的表格 |
| 缺失汇总 | F/G/H 全部缺失时用一句汇总 + 折叠字段清单，不逐字段重复「未提供，不参与判定」 |
| 免责一处 | 免责声明、数据截止、版本号、数据局限收敛到文末「数据说明与风险提示」一节，正文不重复 |
| 名词说明 | 报告末尾提供可折叠术语表，解释 MAE / Wilson / 运气线 / 尾部阈值 / pp 等 |
| 状态图例 | 8 问表格旁给出 ✅/⚠️/❌/未提供 的含义图例 |

**不可动的边界**：三档判断措辞、8 问状态符号、唯一动作结论文案、所有回测数值、
`signal_map.json` 与 `path_map.json` 内容一律不因呈现优化而改变。

## 9. 模式C 适用范围守卫（v1.4）

### 9.1 适用前提

模式C 回答「**组合信号已触发的这一轮下跌**过程中我该怎么办」（见 `SKILL.md` 第 0 节、
5.1）。它的第 1 问「原始结论是否被证伪」在语义上要求**存在过原始结论**，对应的是
「触发过、现在失效」，而不是「从未触发」。因此：

| 状态层输入 | 模式C 是否适用 | 输出 |
| --- | --- | --- |
| 有效组合信号当前触发 | ✅ 适用 | 8 问检查表 + 四选一动作 + 风险预算 + 外部输入 |
| 组合信号从未触发（模式A 判定「观察」或「不具备」） | ❌ 不适用 | 「本轮不适用」简报；**不参与、不加仓** |

### 9.2 守卫规则

`decision.py` 在入口处检查 `combo_hits`；为空时**早退**，只输出一份与成品同规格的
「本轮不适用」简报，包含状态层判断、数据截止、双版本、免责与数据局限，并明确：

1. **不输出** 8 问检查表，因为无「原始结论」可证伪；
2. **不给出** 四选一动作结论，避免对无仓位账户输出「减仓」；
3. **不计算** 仓位上限 / 认错线 / 风险预算，因为路径分布应挂在**当前触发**的组合上；
4. **不追加**决策日志（只增不改的审计台账不得记入无买点的减仓记录）。

### 9.3 为什么不是「特判」

`SKILL.md` 5.5 第 2 条禁止的是「针对某个具体日期、价位、读数或读数区间做特判分支
**直接返回某个动作**」。本守卫是**适用范围判定**（前置条件），不读取任何行情读数做分支，
不改写 `decide()` 的四选一逻辑，也不针对具体日期或价位。改动后：

- `decide()`、`fatal_questions`、`gate_questions`、`actions` 配置**一字不改**；
- 已触发指数的报告与守卫前**逐字节一致**；
- 模式A 三档判断、`signal_map.json`、`path_map.json`、`data/`、`stats/` 一律不动。

用户仍可随时运行 `monitor.py` 查看模式A 全貌；本守卫只约束模式C 的适用对象。
