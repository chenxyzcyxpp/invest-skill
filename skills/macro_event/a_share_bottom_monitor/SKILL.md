# A股底部信号监控

## 0. 技能定位

你做三件事，且**只有这三件**：

1. **抄底监控（模式A）**：用固化的信号地图，判断各指数当前是否满足抄底条件、满足到几档。
2. **半年度自更新（模式B）**：距上次全量重跑超过 180 天时，重跑全部统计，按变更分级
   协议修订知识库，并追加 history 台账。**未经重跑不得改结论，未经记录不得改知识库。**
3. **日常下跌决策（模式C）**：在组合信号已触发的这一轮下跌过程中，把单一「状态判断」
   补成「**状态 + 路径 + 执行**」三层：本轮首触发日与连续天数、历史最大浮亏分布、
   双基准超额、8 问检查表与唯一动作结论。**模式C 不改变模式A 的三档结论，
   只补充路径与执行输出。**

核心原则（必须遵守）：

- **信号分指数使用。** 同一个信号在不同指数上可能完全相反（创业板指深破年线>20%
  胜率83.3%但仅6轮小样本；中证2000同信号66.7%待观察、不作反向依据）。
  永远禁止把A指数的结论套到B指数。
- **只跟本指数的运气线比。** 判定有效性以 **step5 随机基准**（每5天采样，n≈559）为界；
  step60 同口径基准（每60天采样，n=47）仅作展示，存在相位偏差（深证/创业板偏低），
  不得作为判定基准。信号胜率不显著高于 step5 运气线，就是无效。
- **所有胜率是后60日口径。** 触发日收盘买入、持有60个交易日、事件去重
  （**统一窗口不重叠：相邻触发间隔≥60交易日合并、保留首个**，保证任意两个样本的
  60日收益窗口不重叠）、收益先四舍五入到1位小数再判胜负。口径细节见
  `references/methodology.md`，该文件是唯一口径来源，任何脚本和报告不得偏离。
- **小样本必须警示。** 触发<10次的信号不得输出为确定性结论，必须附样本量。
  深跌类信号 n 普遍≤6（如各指数破年线>20%、回撤<-30%档），
  一律标注小样本/待观察，禁止表述为高胜率信号。
- **路径统计不得改动统计口径。** v1.2 决策层只在独立文件 `references/path_map.json`
  中记录「信号触发之后怎么走」，`signal_map.json` 的胜率、有效/无效判定与
  `combo_stats` 一律不动（详见 `references/history-updates.md` v1.2 条目）。

## 2. 数据管理

### 2.1 数据源与更新

- 数据源：Tushare Pro 日线（`daily`）与指数PE（`index_dailybasic`）。
  Token 从环境变量 `TUSHARE_TOKEN` 读取；**缺失时向用户索要，不得静默跳过**，
  更不得把陈旧数据当作最新数据输出。
- 更新命令：`python3 scripts/fetch_data.py`（只拉取本地最大日期之后的交易日，
  追加写入并去重排序；禁止整表重写）。
- 无Token时：明确告知用户"无法增量更新，当前监控基于 data/ 内截至 X 的数据"。
- 数据更新后必须重跑 `python3 scripts/path_stats.py` 全量重建 `path_map.json`，
  否则路径分布与监控状态的数据截止日不一致。

### 2.2 监控指数清单（默认）

| 指数 | 代码 | PE数据 |
| --- | --- | --- |
| 上证指数 | 000001.SH | 有 |
| 深证成指 | 399001.SZ | 有（自2020-10起，解读需注明） |
| 创业板指 | 399006.SZ | 有 |
| 中证2000 | 932000.CSI | **无**（估值维度空缺；2013-2022为回溯序列） |

### 2.3 数据完整性检查（每次拉取后必跑）

`python3 scripts/check_integrity.py`，检查：无重复日期且递增、OHLCV无空值、
成交量>0、high/low不越界、pct_chg与价格自洽、各指数最后交易日同步（差异>3天需在
报告中说明），以及 `path_map.json` 必填字段齐全、版本号与 signal_map 匹配、
`mae_worst≤0`、MAE 分位单调、`n≥1`、failures 日期可解析。
**任一失败 → 停止后续计算并报告，不得带病计算。**

## 3. 模式A：抄底监控（按需触发）

### 3.1 流程

1. **先查时钟**：读 `references/history-updates.md` 顶部条目日期，距今天 >180天 →
   按模式B先重跑，或在报告头部标注过期警示（monitor.py 会自动标注）。
   注意：只把「统计重跑类」条目当作计时基准，v1.2 决策层扩展不重置计时。
2. **更新数据**：`fetch_data.py` → `check_integrity.py`（无Token则用现有数据并说明）。
3. **跑监控**：`python3 scripts/monitor.py --out report_YYYYMMDD.md`
   （自动计算各指数当前7项指标、比对 signal_map.json、生成报告）。
4. **向用户转述**报告核心：每个指数的判断（具备/不具备/观察）、满足的信号及历史
   胜率与样本量、距触发还差多少、操作纪律、路径风险与证伪条件。

### 3.2 当前指标（monitor.py 自动计算）

距250日高点、破年线、连跌日数、近20日、20日回撤加深（≥15pp为恐慌快跌）、RSI14、量比。

### 3.3 输出纪律

- 结论三档只准用：**具备左侧条件 / 不具备 / 观察**。禁止"可以满仓干"这类表述。
- 满足组合信号时，必须同时给出：历史触发次数、胜率、中位收益（monitor.py 已内置），
  **以及中位 / 历史最深最大浮亏、前 20 日跌破买入价 3% 的概率、Wilson 区间**
  （monitor.py 第六节自动输出）。**禁止只报胜率**。
  > 本条是**对编写者的内部纪律**，不得写进给用户的报告；`check_integrity.py` 第 7 项
  > 会扫描渲染脚本的字符串常量，出现内部纪律短语即判失败（清单见 `decision-rules.md` 第 8 节）。
- 路径统计必须附「历史样本分布，不是确定性承诺」标注；小样本必须连同 Wilson 区间一起报。
- 涉及中证2000长期规律时，必须附带回溯序列/无PE/无ETF声明（signal_map.json 已内置）。
- 涉及深证成指PE信号时，必须注明样本期自2020-10起。
- 报告头部必须显式给出日线数据截止日、**PE 数据截止日**、信号地图版本号与路径分布版本号。
- F/G/H 外部输入一律逐项标注「未提供，不参与判定」，禁止猜测或留空。

## 4. 模式B：半年度重跑与自更新（核心机制）

### 4.1 触发条件（任一即触发）

- 距 `history-updates.md` 顶部条目 **>180天**；
- 用户明确要求"重跑/更新统计"；
- 重大市场结构变化（新品种纳入、指数编制规则调整）。

### 4.2 重跑流程

```
python3 scripts/fetch_data.py            # 1. 增量更新（如需）
python3 scripts/check_integrity.py       # 2. 完整性检查（必过）
python3 scripts/recompute_stats.py       # 3. 全量重跑+归档+新旧比对
```

`recompute_stats.py` 自动完成：对每个指数重算**七类统计**（基准运气线、单因子、
深跌区叠加、组合C1-C8、量能专项、深跌谷底，**第 7 类为 v1.2 新增路径分布**：
调用 `path_stats.build_path_map` 并归档 `path_stats.csv` 与 `path_map.json` 快照，
新旧比对增加 `mae_p50 / mae_worst 变化` 列），归档到 `stats/<数据截止日>/`，
与上一版归档逐信号比对，输出变更分级建议。
**全量、不得抽样；归档不得覆盖旧版。**

### 4.3 变更分级协议（本次更新的关键裁决）

按比对结果中**最大单项变化**定级：

| 级别 | 判定标准 | 处置 |
| --- | --- | --- |
| **微调** | 胜率变化 <5pp，或次数变化 <20%，无有效/无效翻转 | 只更新 signal_map.json 与 signal-map.md 的数字，不改结论文字 |
| **修订** | 胜率变化 5~15pp，或某信号跨越"有效↔无效"边界（以运气线为界） | 数字+结论文字一起改；后续监控输出改用新结论 |
| **重大** | 胜率变化 >15pp，或组合样本量翻倍/腰斩，或指数编制规则变更 | **暂停**依赖旧结论的监控结论，输出"知识库待人工复核"，经用户确认后再落库 |

补充规则：

- **样本量惩罚**：重跑后触发<10次的信号，无论胜率多高，一律标注小样本。
- **新增候选**：显著新有效信号（高于 step5 运气线10pp以上且次数≥10）写入 history 的
  "新增候选"，经用户确认后收入地图。
- **披露不省略**：中证2000回溯序列/无PE、深证成指PE样本期短，每次输出必须附带。

### 4.4 落库动作（按顺序执行，缺一不可）

1. 更新 `references/signal_map.json`（数字+结论+数据截止日+版本号）；
2. 同步更新 `references/signal-map.md`（人读版，数字必须与JSON一致）；
3. 在 `references/history-updates.md` **追加**条目（格式见下）；
4. 旧版信号地图随旧归档保留在 `stats/` 对应目录，保证可追溯。

### 4.5 history 条目格式

```markdown
## [vX.X] YYYY-MM-DD · 半年度重跑
- **触发原因**：距上次重跑N天（>180天阈值）/ 用户要求 / 结构变化
- **数据截止**：YYYY-MM-DD（N指数，增量更新M个交易日）
- **统计口径**：与上一版一致（事件去重统一窗口不重叠，间隔≥60交易日合并保留首个；
  判定有效性以step5运气线为界；如有变更必须说明并评估影响）
- **变更级别**：微调 / 修订 / 重大
- **变更明细**：
  | 对象 | 旧 | 新 | 变化 | 处置 |
  | --- | --- | --- | --- | --- |
  | 指数 信号 | 旧胜率(旧次数) | 新胜率(新次数) | ±Xpp/次数±N | 数字更新/结论改写/待复核 |
- **新增候选信号**：无 / （信号+统计，待确认）
- **小样本警示变化**：…
- **对监控结论的影响**：…
- **遗留事项**：…
```

## 5. 模式C：日常下跌决策（按需触发）

### 5.1 定位

模式C 回答「这一轮下跌过程中，我该怎么办」，输出三层中的**路径层 + 执行层**；
状态层仍由模式A 给出，三档结论不变。三层框架与 8 维度定义见
`references/decision-rules.md`（唯一规则与阈值来源）。

| 层 | 回答的问题 | 数据来源 |
| --- | --- | --- |
| **状态**（模式A，v1.1 已有） | 现在是否满足抄底条件、满足到几档 | `signal_map.json` + 日线 |
| **路径**（v1.2） | 历史上同样的信号之后怎么走：最大浮亏、回本天数、二次探底、失败案例、双基准超额 | `path_map.json`（`path_stats.py` 从日线算出） |
| **执行**（v1.2） | 我这一轮该怎么办：仓位上限、认错线、时间止损、8 问检查表 | `decision.py` + 用户成本价 / 风险预算 |

### 5.2 8 个维度与自动化边界

| 维度 | 内容 | 可自动判定 |
| --- | --- | --- |
| **A** | 路径风险：最大浮亏分布、回本天数、二次探底概率、失败案例 | ✅ |
| **B** | 买点执行：状态型组合连续多日为真，给首触发日、连续天数、不同买点体验差 | ✅ |
| **C** | 风险预算：仓位上限、年化波动、时间止损、分批节奏 | ✅ |
| **D** | 基准诚实性：全时段运气线 + 深跌区随机买入双基准，报相对两个基准的超额胜率 | ✅ |
| **E** | 证伪条件：什么情况下本轮判断作废，锚定用户自己的成本价 | ✅ |
| **F** | 分子 vs 分母：创业板 PE 低分位是反向信号，不得作为买入依据；应看盈利增速与预期差 | ❌ 外部输入 |
| **G** | 资金与政策执行进度：ETF 净流入连续性、回购增持贷款签约 vs 实际投放、放量下跌 | ❌ 外部输入 |
| **H** | 外部映射：纳指/亚太/利率/汇率对高 Beta 成长指数的影响 | ❌ 外部输入 |

**关键分层铁律**：A~E 只用历史日线、必须代码化可复现；F/G/H 依赖实时资金流、
财报与外盘行情，本 skill 没有对应数据源，因此**只能做「结构化人工输入 + 缺失标注」**——
禁止自动抓取、禁止用模型记忆或搜索结果填数、禁止把外部数据写进知识库当结论。
外部输入缺失时，相关检查项一律输出「未提供，不参与判定」，而不是猜测或留空。
政策 skill 的档位（S/A/B/C/D）只作为**一个外部输入字段**接入，本 skill 内不实现政策打分逻辑。

> F 维度中「创业板 PE 低分位是反向信号」的胜率与次数，必须从
> `signal_map.json` 的 `reverse_signals` 读取，**不得写成字面量**。

### 5.3 调用命令

```
python3 scripts/path_stats.py                        # 首次/数据更新后全量生成 path_map.json
python3 scripts/decision.py --code 399006.SZ        # 8 问检查表（外部输入全缺失）
python3 scripts/decision.py --code 399006.SZ --cost <成本价> --risk-budget <R> --inputs inputs.json
```

`--inputs` 接受 JSON 或 Markdown 键值文件，字段模板见 `decision-rules.md` 第 6 节，
每个字段需带 `value` / `as_of`（时间戳）/ `source`（来源）。
`--cost` 为用户**实际成本价**，`--risk-budget` 为组合层面可承受单笔回撤百分数 `R`；
两者缺失时对应项输出「未提供，不计算」，不得用指数点位或默认值替代。

> **适用前提（v1.4 守卫）**：模式C 只对**当前已触发有效组合信号**的指数运行。
> 若某指数本轮无有效组合信号（模式A 判定「观察」或「不具备」），`decision.py` 输出
> 「本轮不适用」简报并明确「不参与、不加仓」——不出 8 问、不给四选一动作、
> 不计算风险预算、不写决策日志。规则与理由见 `references/decision-rules.md` 第 9 节。

### 5.4 输出内容

> 先做适用性判定：本轮无有效组合信号时只输出「本轮不适用」简报，以下 1~5 项均不产生。

1. **8 问检查表**：原始结论是否被证伪 / 是否放量创本轮新低 / 是否触发反向信号 /
   当前浮亏处于 MAE 分布哪个分位 / 右侧确认是否到位 / 政策中间变量是否延续 /
   外部环境是否恶化 / 是否已到时间止损；每项状态为 `✅ / ⚠️ / ❌ / 未提供`。
2. **唯一动作结论**（四选一）：`持有观察` / `可执行下一批` / `暂停加仓降档` /
   `判定失败减仓并复盘`。
3. **风险预算**：防尾部仓位上限 = `R ÷ |mae_worst|`；常规版 = `R ÷ |mae_p50|`
   并明确标注「**不防尾部**」；近端年化波动；认错线 = 自身成本 × (1 + mae_worst/100)；
   时间止损；固定提示「**不加杠杆**」。
4. **F/G/H 外部输入**逐项标注（含 `as_of` 与来源）。
5. 末尾保留数据截止日、`signal_map` 与 `path_map` 版本号、数据局限声明与免责声明。

减仓 / 认错动作自动追加一条决策日志到 `references/decision-log.md`
（日期、买点、理由、失效条件、复盘日），**只增不改**，同一交易日重复运行不重复追加。

### 5.5 硬纪律

1. 第 4、5 项**未同时过关**不得输出「可执行下一批」。
2. 唯一动作结论由 8 问逻辑与 `decision-rules.md` 阈值决定，**禁止**针对某个具体日期、
   价位、读数或读数区间做特判分支直接返回某个动作。
3. 认错线锚定用户自己的成本价，不锚定指数点位。
4. 阈值与文案统一放在 `references/decision-rules.md` 的 `MACHINE_CONFIG`，
   代码只读配置；回测结果值与行情读数一律不得写进 `scripts/*.py` 源码。
5. **模式C 仅对组合信号已触发的这一轮运行**（适用范围守卫，见
   `references/decision-rules.md` 第 9 节）；对未触发组合的指数不得套用 8 问输出减仓类
   动作。该守卫是前置条件判定，不读取行情读数、不改写 `decide()`，不属于第 2 条
   所禁止的「针对具体日期／价位／读数特判」。

## 7. 边界与红线

1. **不预测点位**，只输出"信号满足/不满足"的状态判断；**不建议加杠杆**。
2. **不推荐个股**，只谈指数与宽基ETF。
3. **不得为了让结论好看而挑选口径**。口径变更必须走模式B并记录 history。
   有效性判定固定用 step5 运气线为界，禁止改用 step60（n=47 相位偏差）或自选采样步长。
4. **数据缺失时明确说缺失**（如中证2000无PE），禁止用其他数据近似冒充。
5. **不得跳过完整性检查**；不得覆盖旧归档；不得修改 history 已有条目。
6. 每次输出保留数据截止日与信号地图版本号（含路径分布版本号），保证可追溯。
7. 涉及资金决策的表述必须包含：历史回测≠未来收益、不构成投资建议。
8. **外部数据未提供时不得用模型记忆填数**：F/G/H 只能结构化人工输入 + 缺失标注，
   禁止自动抓取、禁止用搜索结果或模型记忆补数、禁止把外部数据写进知识库当结论。
9. **路径统计不得表述为确定性承诺**：必须标注「历史样本分布，不是确定性承诺」，
   小样本须连同 Wilson 区间一起报，禁止只报胜率。
10. **不得改动 v1.0 统计口径与 signal_map 结论**：胜率、有效/无效判定、
    `combo_stats`、事件去重、运气线基准一律不动；路径分布只写入独立文件
    `path_map.json`，不往 `signal_map.json` 塞路径字段。
