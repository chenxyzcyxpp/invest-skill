# 数据源与实现说明

本文档记录行业速报 skill 的数据接口细节、三级降级路径与已知限制，
供后续维护与故障排查使用。脚本实现见 `scripts/industry_flash.py`。

## 一、行业行情数据源（三级可降级）

行业速报的强弱榜 / 资金流依赖「行业级行情」。三源按优先级降级：

### 1.1 Tushare（优先）

| 用途 | 接口 | 说明 |
|---|---|---|
| 申万行业指数行情 | `index_daily`（ts_code = 申万行业指数代码，如 `801080.SH` 电子、`801730.SH` 电气设备） | 字段 `pct_chg`（当日 %）、`pct_chg_5d`（近5日 %，或自算）、`amount` |
| 行业成分股 | `industry_classified` / `index_member` | 拿到行业 → 成分股列表，用于「成分股聚合」兜底 |
| 个股行情 | `daily` / `daily_basic` | 成分股聚合行业涨跌幅、换手 |
| 行业资金 | `moneyflow_ind`（如有权限） | 行业主力净流入；无权限则走 Akshare |

> 申万行业指数代码映射见 `scripts/industry_flash.py` 的 `SW_INDUSTRIES`（行业名 → 指数代码）。
> Tushare token 从 `~/.hermes/config.yaml` 提取（与 sentiment 一致）。

### 1.2 Akshare（次级）

| 用途 | 接口 | 说明 |
|---|---|---|
| 行业板块行情 | `ak.stock_board_industry_name_em()` | 东方财富行业板块，含 `涨跌幅`、`换手率`、`总市值`、`主力净流入`（板块口径） |

> 东方财富板块口径为「板块主力净流入」，与 Tushare 个股加总口径不完全一致，报告须标注实际使用源。

### 1.3 腾讯财经网页源（兜底）

- 行业板块页面 HTML 解析（板块涨跌幅 / 换手）。解析脆弱，仅作最后兜底，失败不阻断主流程。

### 1.4 演示数据兜底

- 无 token / 三源不可达时，`--demo` 使用内置演示数据（申万一级 31 行业的 pct1d / pct5d / turnover / 资金），**仅验证管线**，报告标 `degraded=demo`。

## 二、行业新闻 / 事件源（弱，需重点说明）

**现状缺口**：Tushare / Akshare / 腾讯 三源体系对「行业级新闻 / 事件」覆盖很弱——
Tushare `pro.news` 常无权限，Akshare 板块接口不含新闻，腾讯板块页新闻稀疏。

**当前方案**：

1. R05 事件驱动信号优先复用 `sentiment_risk_warning` 的事件流（全市场新闻按行业归类）；
2. 或经 `WebSearch` 检索近 N 日行业关键词新闻（标题 / 来源 / 时间）；
3. 新闻源不可达时，R05 信号在报告中标注「事件源不可用」，不伪造事件。

## 三、三级降级路径

| 数据项 | 降级顺序 | 兜底 |
|---|---|---|
| 行业行情（涨跌幅 / 换手） | Tushare 指数 → Akshare 板块 → 腾讯 HTML → 演示 | 成分股聚合（Tushare 指数无权限时） |
| 行业资金流 | Tushare `moneyflow_ind` → Akshare 板块主力净流入 → 演示 | 无则标注缺失 |
| 行业新闻 / 事件 | sentiment 事件流 / WebSearch → 标注缺失 | R05 降级，不伪造 |

失败后行为：

- 全源失败（行情三源皆失败）：抛 `IND_FLASH_001`，脚本退出，**不输出伪造速报**。
- 部分源失败：标 `degraded=partial`，`degrade_trace` 记录各源成败，报告继续生成。

## 四、单位与口径

| 字段 | 单位 | 说明 |
|---|---|---|
| pct1d / pct5d | % | 当日 / 近 5 日涨跌幅，直接使用 |
| turnover | % | 换手率 |
| net_inflow | 亿元 | 主力净流入（板块口径） |
| inflow_ratio | % | 净流入 / 成交额 |

## 五、已知限制

1. 行业口径为申万一级（31 个）；二级 / 三级需扩展映射表。
2. Tushare 行业资金（`moneyflow_ind`）需权限；无权限时资金流走 Akshare 板块口径。
3. 腾讯网页源解析脆弱，仅兜底；结构变动即失效。
4. 行业新闻源薄弱，R05 事件可能不全（见第二节）。
5. 演示数据仅用于管线验证，不构成真实速报。

## 六、对框架的反哺建议（待评审）

1. **评估接入第四资讯源**：行业级新闻在三源体系中覆盖弱，建议引入专业资讯源（如财联社 / 同花顺资讯接口）专供 R05。
2. **复用舆情事件流**：与 `sentiment_risk_warning` 共建统一「事件流」服务，避免重复检索。
3. **统一行业口径**：推动 `market_hotspot` / `macro_analysis` 共用同一套申万行业映射（当前各自维护）。
4. **网关补行业资金接口**：在架构第三层可降级网关补齐行业资金流，使本 Skill 可经 `ctx.gateway` 取数（当前 `calls_gateway: false`，直连数据源，待适配 `base_skill`）。
