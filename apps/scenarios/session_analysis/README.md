# 盘前 / 午盘 / 盘后 综合分析（session_analysis）

> 应用层场景 · 作者 **Warwick** · v1.0.0 · 直接取代旧三空壳场景 `pre_market` / `intraday` / `closing`。

把已有的 15 个分析 Skill 按「盘前 / 午盘 / 盘后」编排成综合分析，产出**可追溯的 Markdown 报告 + 可分享的 PNG 卡片**。

## 一句话理解

**这是编排层，不是分析层。** 它不新增任何分析，只按一份声明式配方（`recipes/session_map.yaml`）逐个调用上游 Skill，把结论汇总成品化交付——所以每次 Skill 更新，它自动跟着迭代。

## 目录结构

```
session_analysis/
├── SKILL.md                    # 给 Agent 的聚合执行提示词（读配方→执行→组装双产出）
├── manifest.yaml               # 场景契约（作者/版本/依赖/取代关系）
├── workflow.yaml               # 编排引擎发现契约（Skill 槽位）
├── README.md                   # 本文件
├── DESIGN.md                   # 设计方案与 SOP 采纳判断
├── recipes/
│   ├── session_map.yaml        # ★ 可迭代核心：时段→Skill/卡型/口径/顺序/依赖
│   └── report_template.md      # MD 报告骨架
└── examples/                   # 真实历史数据样例（MD + PNG）
```

## 三个时段（对齐投研作业流程 SOP）

| 时段 | 窗口 | 步数 | 数据来源 | 状态 |
| --- | --- | --- | --- | --- |
| 盘前 `pre_market` | 08:30–09:25 | 6 步 | SOP 实战流程 | ✅ 已采纳 |
| 午盘 `midday` | 11:30–13:00 | 3 步 | SOP 未覆盖 | ⚠️ 实验性建议组合 |
| 盘后 `closing` | 15:10–20:00 | 7 步 | SOP 实战流程 | ✅ 已采纳 |

## 怎么调用

对 Agent 说人话即可，例如：
- 「做一份今天的**盘后综合分析**」
- 「**盘前**帮我梳理隔夜外围、政策和风险」
- 「**午盘速览**」（实验性）

Agent 会加载本场景 `SKILL.md`，读 `session_map.yaml` 锁定对应时段，按 SOP 时点纪律逐个执行上游 Skill，产出 MD + PNG。

## 迭代（关键设计）

| 变化 | 要做什么 |
| --- | --- |
| 某 Skill 升级 | **什么都不用改**——自动读该 Skill 最新 `SKILL.md` |
| 新增 Skill | 在 `session_map.yaml` 加一行 step（新卡型先在 `presentation/` 补映射） |
| 调整组合/口径/依赖 | 只改 `session_map.yaml` 对应字段 |
| 报告模板变化 | 只改 `report_template.md` |

## 设计要点（来自 SOP）

1. **时点纪律**：盘前严格锁定 09:25 前信息（K线截到前一交易日、剔除当日收评），防同日舆情口径正负反转导致结论失真；
2. **失败隔离**：凭据缺失/限流如实记入「数据缺口」，不编造、不拖垮整场；
3. **依赖跳过**：重点公司验证依赖策略持仓池，无输入则不产出（SOP 实战原样保留）。
