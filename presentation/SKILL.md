# invest-skill 小白卡生成器（invest-novice-cards）

> 版本 2.0.0 · 2026-11-24 入库本库 · 隶属 presentation 输出层（与 skills/base/ 平行，非 15 个分析 Skill 之一）
> **v2 变更**：① 新增第 0 节「场景与触发协议」——什么交互进卡、进哪张卡；② 单卡纪律：进卡交互只回一张卡 + 一句引导语，禁止文字总结；③ 数据新鲜度协议（`data_as_of` 字段 + 各卡型时效）；④ 政策托底等复杂卡全面降门槛（档位字母→力度人话、T+N→1 周/1 月/3 月）。
> **定位：翻译层，不是分析层。** 上游技能（本库 `skills/`，Apache-2.0）负责分析与取数，产出报告；本技能只做一件事：把报告翻译成小白卡片。不新增任何分析、不改动上游结论、数字逐字段照抄。
> 与底部信号卡的关系：本输出层覆盖全部 15 个上游 Skill。底部信号（a_share_bottom_monitor）的 SignalCard 沿用本层既有话术与渲染口径（见第 3 节），风格同源，且**同受第 0 节场景协议约束**。

## 0. 场景与触发协议（v2 新增；本技能的入口，先读这节再用后面所有节）

### 0.1 触发路由：用户什么交互，进什么卡

宿主 Agent 每次收到用户消息，先做**意图匹配**（语义优先，关键词只是示例），命中即进入小白卡交互：

**A. 用户主动问（对话触发）**

| 用户典型说法（示例，非穷举） | 进入卡型 | 来源技能 |
|---|---|---|
| "今天大盘怎么样""今天涨跌""收盘了吗""今天亏麻了" | 今日收盘卡 `daily` | market_daily_review |
| "昨晚外面市场怎么样""开盘前有什么要知道的""隔夜呢" | 隔夜五件事卡 `overnight` | overnight_review |
| "现在能抄底吗""大盘见底了吗""是不是底了" | 底部信号卡（技术面）为主；用户明确问政策时进政策托底卡 | a_share_bottom_monitor / policy_bottom_monitor |
| "出了什么政策""XX 政策什么意思""新政策对股市有什么影响" | 政策解读卡 `policy` | policy_interpret |
| "今天什么板块强""哪个行业涨得好""钱都流向哪了" | 行业强弱卡 `industry` | industry_brief |
| "今天在炒什么""有什么热点""XX 怎么突然涨了" | 热点速览卡 `hotspot` | market_hotspot |
| "XX 概念是怎么回事""XX 产业链怎么看" | 产业链地图卡 `chain` | concept_chain_analysis |
| "明天会不会大跌""市场情绪怎么样""明天稳不稳" | 风险预警卡 `sentiment` | sentiment_risk_warning |
| "现在宏观环境怎么样""大环境如何" | 宏观时钟卡 `macro` | macro_analysis |
| "XX 股票怎么样""帮我看看 XX""XX 能拿吗" | 个股体检卡 `stock5d` | stock_5d_deep_analysis |
| "XX 和 YY 哪个好""帮我比比这几只" | 对比选购卡 `stockcmp` | stock_comparative_analysis |
| "量化策略现在拿着什么""选股池呢" | 策略选股池卡 `quantpick` | racing_quant_pick |
| "XX 成长股怎么样""有什么高成长标的" | 成长观察卡 `growth` | aggressive_growth_strategy |
| "XX 值不值得长期拿""现在贵不贵""这家公司好不好" | 价值投资卡 `value` | value_investing |

**B. 系统到点推（定时触发）**

| 时刻 | 推送卡 |
|---|---|
| 开盘前（如 08:30） | 隔夜五件事卡 `overnight` |
| 收盘后（如 15:30） | 今日收盘卡 `daily` |
| 政策引擎检测到新政策 | 政策解读卡 `policy` / 政策托底卡 `policy_bottom` |
| 底部信号亮灯 | 底部信号卡 |

**一次消息只命中一个意图**：用户一句话问了两个事（"大盘怎么样，XX 股票呢"）→ 只出第一问的卡，引导语里带一句"您还问了 XX，要看的话说一声"；**绝不连发两张卡**。

### 0.2 单卡纪律：一问一卡一图（宿主输出协议）

进入小白卡交互后，**回复的全部内容 = 一句引导语 + 一张卡**，然后结束：

- 引导语 ≤ 20 字，例如"您问的大盘，看这张卡"；
- 卡 = PNG 图片（聊天宿主）或文本话术版（降级），**卡就是全部信息**；
- **禁止**：贴卡前先来一段"总结如下…"；贴卡后再"简单总结一下"；一次连发多张卡；在卡外补充数据或观点。

为什么这么严：文字总结和卡并存时，用户会先读文字、把卡当配图，而文字的口径没有经过话术表与红线约束——出了卡又出总结，等于绕开了本技能的全部纪律。**卡没说清楚是卡的问题，改卡，不是加文字补救。**

追问处理：用户看完卡追问 → 按追问内容重新路由——问术语（"T+60 是啥"）→ 一句文字解释（用第 2 节术语表右列口径）；要看详细 → 给上游报告原文（Pro 通道）；换话题 → 重新走 0.1 路由。

### 0.3 数据新鲜度：宁可不卡，不可旧卡

契约新增 `data_as_of` 字段（数据实际截至时间，YYYY-MM-DD 或 YYYY-MM-DD HH:MM），组装卡的一方在出卡前先做时效判定：

| 卡型 | 最大时效 | 盘中/非交易日规则 | 超龄处理 |
|---|---|---|---|
| `daily` / `industry` / `hotspot` | 当个交易日 | 盘中（15:00 前）请求 → 用昨收数据出卡，卡头标"截至昨日收盘"；非交易日 → 最近交易日 + 标日期 | 不出卡，回"最新数据到 X 月 X 日" |
| `overnight` | 当日开盘前 | 盘中再问 → 引导去看 `daily` | 不出卡 |
| `sentiment` | 当日（预测次日） | — | 不出卡 |
| `stock5d` / `stockcmp` | 数据日期 ≤5 个交易日 | — | 不出卡 |
| `macro` | ≤35 天 | — | 可出卡，卡头显著标日期 |
| `policy` / `policy_bottom` | 事件型长效 | — | 可出卡，卡头显著标日期 |
| `quantpick` / `growth` | 最新一期（跨期前） | — | 可出卡，标"第 X 期" |

- 判定责任在组装方（宿主 Agent / 定时管线）：超龄 → **不出卡**，如实告知数据到哪天，绝不拿旧数据冒充今天。
- 渲染器职责：卡头显示"截至 {data_as_of}"徽标；字段缺失时 stderr 警告（v2 契约必填）。
- `date`（报告数据日期）与 `data_as_of`（数据实际截至）是两个字段：事件型卡 date=事件日、data_as_of=数据建库/生成时刻；行情型卡两者通常相同。

### 0.4 不进卡清单（以下场景走普通对话，不强行出卡）

1. **数据超龄**（0.3 判定不过）→ 一句话说明数据到哪天。
2. **上游没覆盖**：基金类问题（fund_* 四技能为占位）→ 如实说"基金分析还没上线"。
3. **用户要深度**：明确说"详细说说""给我完整报告""原文"→ 走 Pro 通道给上游报告原文。
4. **与行情无关的闲聊** → 正常对话。
5. **无法唯一确定意图**（说了三四个话题）→ 请用户挑一个，最多澄清一次。

### 0.5 出卡前三秒自查（有一条不过 → 改卡再出，不许靠加文字补救）

1. `headline` ≤14 字，主谓宾人话（"这是历史上力度大的托底政策"✓；"S 级增量资金组合拳"✗）；
2. `say` 首句无未翻译术语（对照第 2 节术语表）；
3. 每个数字带单位与时间口径（"+21.9%"要能读出"多久之内"）;
4. 每张图 cap 带口径说明；5. `data_as_of` 已填且通过 0.3 判定。

## 1. 自动生成管线（三种用法，任选其一）

```
用户交互 / 定时事件 ──0.1 路由──▶ 命中卡型 + 0.3 时效判定通过
        │ 按第 4 节模板提取字段
        ▼
上游技能产出报告（Markdown / JSON）
        │
        ▼
NoviceCard JSON（invest-novice-card/1，含 data_as_of）
        │
        ├─ 用法 A：宿主 Agent 纯对话组装（零依赖，LLM 按第 4 节话术表填卡）
        ├─ 用法 B：本机确定性渲染  .venv\Scripts\python -X utf8 src\render_invest_cards.py cards.json -o cards.html --png cards.png
        └─ 用法 C：双渲染一致性验收——同一 JSON 两路各渲一遍，数字逐字段比对
        │
        ▼
0.2 单卡纪律输出：一句引导语 + 一张卡（PNG）
```

- 用法 A 给九方智投 / WorkBuddy 等标准 Skill 宿主：不装 Python，话术与模板全部写死在本文，LLM 只做提取与组装。
- 用法 B 给本机 / VPS：`scripts/render_cards.py` 读 JSON 数组输出 HTML（中间格式），卡片视觉（`nv-*` 类名、两层配色口径）已内置于渲染器，可挂 systemd/cron 定时产出。
- **最终交付形态（聊天宿主）**：聊天窗口跑不了 HTML，发给用户的是**整页 PNG 图片**。渲染器 `--png` 一条命令完成——两遍无头 Chrome（先 `--dump-dom` 实测页高，再按实高整页截图），820px 宽竖版，需本机 Chrome/Edge（环境变量 `CHROME` 可指定路径）。宿主三种落地：
  1. 宿主有代码沙箱 → 沙箱内跑渲染器 `--png` 直接回图；
  2. 宿主只能发文字/图链 → 本机或 VPS 预渲染 PNG 存图床，Agent 在聊天里回图片链接（可挂 systemd/cron 定时）；
  3. 宿主连图片都不支持 → 降级纯文本话术版（第 4 节话术表本身就是完整文本，档位 emoji 🔴🟡🟢⚪ 照用），零依赖兜底。
- **验收纪律（C）**：任何卡型首次上线或话术表变更，必须两路各渲一次、逐字段核对数字一致后才可发布。

## 2. NoviceCard 通用契约（schema `invest-novice-card/1`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema` | str | 固定 `"invest-novice-card/1"` |
| `card_type` | str | 第 3 节 15 种卡型之一 |
| `title` | str | 卡头标题（如"政策托底 · 央行降准 0.5%"） |
| `date` | str | 报告数据日期 YYYY-MM-DD（照抄上游，不是生成日期） |
| `data_as_of` | str | **v2 必填**。数据实际截至时间 YYYY-MM-DD[ HH:MM]——行情拉取时刻 / 报告生成时刻，卡头"截至"徽标用（见 0.3） |
| `source` | obj | `{skill, version}`——上游技能 id 与版本，逐字照抄其 manifest |
| `headline.tier` | str | `red/yellow/grey/green/neutral`（操作信号语义，见下） |
| `headline.text` | str | 大字结论，≤14 字，主谓宾人话，来自该卡型话术表 |
| `say` | str | 正文话术：话术表原文 + 槽位填上游数字 |
| `chips` | list | 卡尾一行胶囊：`{text, tone: up/down/gold/flat}` |
| `facts` | list | 键值事实行：`{k, v}`——谁发布、文号、样本量等 |
| `figures` | list | 图解（kind 与 data 见渲染器文档），0–2 个，信息位固定 |
| `evidence` | list | 折叠证据行：来源、口径、上游标注 |
| `small_sample` | obj/null | `{n}`——上游样本 <10 时必填，触发小样本警示句 |
| `disclaimer` | str | 固定免责句，一字不改（第 6 节） |

**配色语义（两层口径，全线统一，不得混用）：**
- **行情数值图**（涨跌数字、指数条形、温度计）：红 = 涨/正，绿 = 跌/负；
- **操作信号图**（信号灯、档位徽章、顶条）：红 = 机会/赢面大，黄 = 观望，绿 = 警示，灰 = 等待；
- `neutral`（蓝金点缀）：无操作含义的信息卡（政策解读、热点、收评……）默认档。

**术语→人话翻译表（写死；`say`、图注、facts 值用右列口径；档位字母也按此表翻译，判定与数字不动）：**

| 术语 | 小白版 |
|---|---|
| 胜率 83.3% | 100 次里赢 83 次 |
| 最大回撤 -30% | 从高点跌下来最深跌了三成 |
| 破年线 | 价格跌破了过去一年的平均成本线 |
| 量比 0.63 | 今天的成交量只有平时的 0.63 倍（明显缩量） |
| 北向资金 | 香港那边的外资通过沪深股通买 A 股的钱 |
| 估值分位 30% | 现在的价钱比近 3 年里 70% 的时候都便宜 |
| 组合拳/第几击 | 一套政策里打出来的第几招 |
| 波动率风险 | 接下来可能大起大落的风险 |
| 产业链上游 | 离原材料最近的那一段 |
| S/A/B/C/D 级（政策力度五档） | S=强刺激、A=较大力度、B=一般、C=口头安抚、D=收紧。卡上写"力度：强刺激（S 级）" |
| T+5 / T+20 / T+60 | 买入后第 5/20/60 个交易日 ≈ 之后 1 周 / 1 个月 / 3 个月。标签用人话，cap 保留交易日语境 |
| 增量资金 | 真金白银新进场买股票的钱（如互换便利、回购增持再贷款） |

## 4. 逐卡型模板（话术表写死——之外零即兴）

> 通用规则先立三条：① `say` 模板槽位只填上游数字，禁止改写句式；② 上游报告标注"数据缺失/N/A/源不可用"的字段，卡片原样标"—"并保留缺失说明；③ 上游"观点/推演"字段进卡时必须带"（报告观点）"尾标，与实测事实区分。

### 4.1 政策解读卡（policy_interpret → `policy`）

提取：标题/发布机构/文号/发布时间/政策类型（facts）→ 核心内容与受益行业（`references/EXAMPLE_OUTPUT.md` 的 JSON 结构 `analysisResults` / `benefitIndustries`）→ 风险提示。

| tier | 标题 | 正文 |
|---|---|---|
| neutral | 出了一份新政策，跟你相关的在这里 | {发布机构}发布了《{标题}》。一句话说：{政策解读字段首句}。跟股市有关的主要是 {受益行业前 3} 这些行业。 |

- chips：`受益行业 {n} 个`（gold）＋`风险提示见卡片底部`（flat）
- figures：list（受益行业逐条，head=行业名，text=上游一句影响说明；无说明则省 text）
- 红线特例：政策解读卡的"受益行业"是上游分析结论，chips 必须带"（报告观点）"；**禁止**在卡内出现"利好=会涨"的表述。

### 4.2 政策托底卡（policy_bottom_monitor → `policy_bottom`）

提取：当前政策分级（S/A/B/C/D，双轴判定）→ 工具与位置 → 历史同级别统计（T+60 中位/胜率、样本量）→ 组合进度（第几击）→ 该事件实际 T+N 走势（若有）。

| tier | 标题 | 正文 |
|---|---|---|
| S/A 级 | red | 这是历史上力度大的托底政策 | 这次是{工具人话，如"真金白银进场买股票的钱"}类政策，力度属于{档位人话}（{字母} 级）。历史上出这类政策后 3 个月，市场多数是涨的（100 次里赢 {胜率取整} 次）。但政策是放大器不是发令枪：它让底部更可能成立，不保证马上涨。 |
| B/C 级 | yellow | 政策出了，力度一般 | 这类政策历史上效果一般：3 个月的中等水平只有 {中位}%（{n} 次）。先看着，等更有力的工具。 |
| D 级 | green | 这个机制历史上是反作用 | 同类机制历史上出现后市场反而更差（{n} 次）。别把它当利好。 |

- figures：meter（**levels 用人话五档**：`["强刺激","较大力度","一般","口头安抚","收紧"]`，active=当前档；cap 标注对应字母，如"政策力度五档（本次=强刺激，S 级）"）＋ bars（该事件实际 T+N 走势：**标签"后 1 周/后 1 个月/后 3 个月"**，cap 写明口径"政策落地后上证实际走势（5/20/60 个交易日 ≈ 1 周/1 月/3 月）"）或 winbar（同级历史胜率，n 不足 10 只标"样本少"）
- chips：`第 {k} 击`（组合进度，gold）＋`位置：深跌区/中性区/浅跌区`（flat）
- 红线特例：26 条政策/17 组合是全库小样本，`small_sample` 必填；"政策底≠市场底"必须出现在 evidence；**档位字母翻人话（S→强刺激）是标签翻译不是数字加工，判定与统计数字不动**。

### 4.3 风险预警卡（sentiment_risk_warning → `sentiment`）

|---|---|---|---|
| 高（≥70） | green | 明天可能大起大落，捂紧口袋 | 模型判断明天市场波动风险高（综合分 {score}）。这不是说一定跌，是说上蹿下跳的概率大——别在剧烈波动里追涨杀跌。 |
| 中（40–69） | yellow | 明天波动可能不小，留个心眼 | 综合风险分 {score}。正常操作可以，但别满仓押单边。 |

- 红线特例：这是**预测模型的输出**，headline 旁必须挂"模型预测"小标；综合分照抄，禁止换算。

提取：标的与现价（facts）→ 五步结论（宏观 / 行业 / 公司质量 / 估值 / 综合）→ 四层打分卡（宏观 15% / 行业 25% / 质量 30% / 估值 30%）→ 数据缺口。

| tier | 标题 | 正文 |
|---|---|---|
| neutral | 这只股票，值不值得长期看 | {名称}（{代码}）现价 {价}。报告按五步看：大环境 {宏观一句}、行业 {行业一句}、公司质量 {质量一句}、估值 {估值一句}。四层打分 {总分}（宏观/行业/质量/估值）。**记住：好公司不等于好股票，价值不等于价格**——这是分析，不是买卖建议。 |

- figures：bars（四层得分，neutral 信息口径；估值覆盖不足时上游不出总分，卡内画"—"并保留缺口说明）

## 5. 通用红线（违反即废卡；0.2/0.3 协议与本章同效）

1. **数字零加工**：胜率/样本/收益/分数逐字段照抄上游报告，禁止重算、四舍五入到一位小数以外、单位换算。**档位字母翻人话（S→强刺激）与 T+N 标签换算（60 交易日→3 个月）是标签翻译，判定与数值不动。**
2. **事实与观点分离**：上游实测数据不标注；上游观点/推演/评级必须带"（报告观点）/（模型预测）"尾标。
3. **缺失如实**：上游标 N/A 的字段，卡内画"—"并保留缺失说明，禁止估算补齐。
4. **不给买卖指令**：指数卡最多到"档位指引"（分批/观察/等待）；个股卡一律 neutral，只诊股不荐股；禁止目标价、收益承诺、仓位指令。
5. **话术表即全部**：15 张卡型的话术之外零即兴；新增话术必须走评审并同步双渲染。
6. **小样本必警**：上游任何统计 n<10，卡内必须附小样本句（见第 5 节句式）。
7. **免责固定**：每卡卡尾一字不改带上第 6 节免责句。
8. **HTML 宿主粗体用 `<b>`**，不用 markdown `**`。
